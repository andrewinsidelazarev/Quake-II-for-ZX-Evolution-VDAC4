# Q2.ELF — Quake 2 на ESP32-S3 платы VDAC4

Модуль (приложение) прошивки ESP VDAC4, как DOOM.ELF: прошивка грузит его в PSRAM и связывает со своими
таблицами символов. ESP ведёт игру, сервер и клиент, обходит карту и готовит многоугольники; рисует их
ядро «бомж-3D» в Tang (`gpu/`), команды идут по LINK.

## Сборка

```
powershell -File E:\zx\Quake2\esp\build.ps1
```

Итог — `build\esp\Q2.ELF`. Сценарий делает рендер `ref_esp` (`measure\patches\p06_ref_esp.py`), собирает
проект ESP-IDF 6.0 (`E:\zx\esp`) в `build\esp\idf`, проверяет символы модуля (`check_module_symbols.py`
дерева VDAC4) и печатает размеры секций.

Тот же движок, игра и рендер на ПК — `q2esp.exe` (`measure\build.py --port`): его поток команд сверяется
с эталоном `ref_bz` бит в бит (`tools\bzcmd_cmp.py`).

## Файлы

| Файл | Что делает |
|---|---|
| `main/q2_app.c` | вход модуля (`zm_app_t`), задача игры (ядро 1, приоритет 1, стек 192 КБ в PSRAM), выход, замер раз в 5 с |
| `main/sys_esp.c` | `Sys_*`: время, ошибки, консоль в журнал ESP, память Hunk цепочкой кусков, поиск файлов |
| `main/vid_esp.c` | видео: рендер в этом же модуле (`GetRefAPI`), режимы, 12 — 424×240 |
| `main/swimp_esp.c` | режим экрана и конец кадра рендера: `BZ_EndFrame` → LINK |
| `main/bz_link.c` | загрузка ядра `Q2` (`core_load`), размер картинки из слота 0, поток команд в очередь ядра |
| `main/net_esp.c` | сеть: только петля клиент ↔ сервер |
| `main/store_esp.c` | хранилище pak: `data_open/data_read/data_close` (ABI 1.20) — pak с карты Evo в кэше на флешке USB `/SYSTEM/CACHE/Q2/`, без флешки — с карты Evo по запросу у программы Z80 (прошивка 0.1.166) |
| `main/compat.c`, `compat.h` | libc, которой прошивка модулю не даёт: файлы (запись — в память), `vsprintf`, `sscanf`, `strtok`… |
| `main/zm_app.h` | копия интерфейса приложений VDAC4 (ABI 1.20) |

  клавиша — выход);

# «Бомж-3D» адаптер: спецификация (версия 0.4, 24.11.2026)

Договор между ESP (передний край), C-моделью (`gpu/model/bomzh.c`) и будущим Verilog. Всё, что здесь
написано, C-модель делает **бит в бит**; RTL обязан дать те же точки кадра. Замысел и оценки — `GPU.md`.
Отличия от `GPU.md` — в конце («Что изменилось против GPU.md»).

## Память и экран

- SDRAM 8 МБ, адрес байтовый. Кадр — 8 бит на точку (индекс палитры), z — 16 бит на точку (младший
  байт первым). Шаг строки кадра и z — **S = W, округлённая вверх до 16** (424 → 432): кусок z из 16
  точек — ровно пачка SDRAM 32 байта по выровненному адресу, кусок цвета — 16 байт.
- В кристалле (BSRAM): colormap 64×256 байт, палитра 256×RGB, таблица волны 128 × int32.
  Таблица прозрачности Quake (alphamap 256×256) лежит в SDRAM.
- Всё это задаёт команда `SETUP`: таблицы сначала пишутся в SDRAM командой `WRITE`, `SETUP` копирует
  colormap, палитру и волну к себе.

## Числа

| Обозначение | Формат | Смысл |
|---|---|---|
| `xy` | два int16: x — младшие 16 бит, y — старшие; Q12.4 | вершина на экране; (0,0) — левый верхний угол экрана |
| `zi` | int32 Q2.30 | 1/z (z — глубина в пространстве вида, единицы мира) |
| `su`, `tv` | int32 Q12.20 | s·zi, t·zi — для перспективы |
| `s`, `t` | int32 Q16.16 | координаты текселя на выбранном mip |
| `l` | int32 Q16.16 | свет модели: целая часть 0…16383 (как `llight` Quake), строка colormap = `l >> 24` |
| градиент | 3 × int32 `{C, A, B}` | значение в точке (0,0), прибавка на +1 точку по x и по y |

Значение градиента в точке (x, y) (x, y — целые номера точек): `C + A·x + B·y` по модулю 2^32.
Точка (x, y) — это центр (x + ½, y + ½) в координатах вершин.

## Команды

Слова по 32 бита. В первом слове `[31:24]` — код, `[23:0]` — поля команды.

| Код | Команда | Слов | Поля |
|---|---|---|---|
| 0x01 | `TEX` | 3 | w0 `[16]` LINEAR, `[15:0]` ширина LINEAR; w1 адрес; w2 TILED: `[3:0]` log2 W, `[7:4]` log2 H; LINEAR: `[15:0]` высота, `[31:16]` шаг строки |
| 0x02 | `LMAP` | 5 | w1 адрес; w2 `[15:0]` клеток в строке, `[23:16]` строк, `[27:24]` сдвиг (= 4 − mip); w3 smin (Q16.16); w4 tmin (Q16.16) |
| 0x03 | `POLY` | 1+n+9 (+3) | w0 `[7:0]` n вершин (3…16), `[23:8]` режим; n слов `xy`; градиенты `zi`, `u`, `v` и при свете по вершинам — `l` |
| 0x04 | `POINT` | 3 | w0 `[7:0]` цвет, `[11:8]` размер 1…15, `[13:12]` прозрачность (0, 1 = 33 %, 2 = 66 %); w1 x, y (int16, целые точки); w2 `zi` |
| 0x05 | `PIC` | 7 | w0 `[0]` ключ 255; w1 x, y (int16); w2 ширина, высота (uint16); w3 адрес; w4 шаг строки; w5 шаг s (Q16.16); w6 шаг t (Q16.16) |
| 0x06 | `FILL` | 4 | w0 `[0]` цель: 0 — кадр, 1 — z; `[1]` затемнение кадра; w1 x, y (int16); w2 ширина, высота; w3 значение (8 бит кадра или 16 бит z) |
| 0x07 | `FRAME` | 2 | смена кадров на гашении; w1 вспышка: R `[7:0]`, G `[15:8]`, B `[23:16]`, доля A `[31:24]` |
| 0x08 | `TIME` | 2 | w1 фаза волны 0…127 |
| 0x09 | `WRITE` | 2+n | w0 `[23:0]` n; w1 адрес (кратен 4); n слов данных в SDRAM, младший байт первым |
| 0x0A | `SETUP` | 9 | w1 кадр 0; w2 кадр 1; w3 z; w4 W `[15:0]`, H `[31:16]`; w5 colormap (16 КБ, копируется); w6 alphamap (остаётся в SDRAM); w7 палитра (768 Б, копируется); w8 волна (128 × int32, копируется). Рисуется кадр 0, ножницы — весь экран |
| 0x0B | `SCISSOR` | 3 | w1 x0, y0; w2 x1, y1 (не включая) — для `POLY` и `POINT` |
| 0x0C | `VBUF` | 1+3n | w0 `[9:0]` n (1…512); на вершину: {x, y} (int16, целые точки экрана), zi (Q2.30), свет l (целое 0…16383) — в буфер вершин с номера 0 |
| 0x0D | `STBUF` | 1+n | w0 `[9:0]` n (1…512); на точку шкурки: {s, t} (int16, целые тексели) — в буфер st с номера 0 |
| 0x0E | `TRIS` | 1+2n | w0 `[7:0]` n (1…255), `[23:8]` режим (как у `POLY`, без `PERSP`); на треугольник: {i0, i1, i2} и {j0, j1, j2} — по 9 бит, номера в буферах вершин и st |
| 0x0F | `MARK` | 2 | w1 — число в регистр MARK (LINK 0x90): всё, что шло в потоке раньше, выполнено (`WRITE` — в SDRAM). С 0.4 |

Режим `POLY` (биты w0 `[23:8]`, номера от 0):

| Бит | Имя | Смысл |
|---|---|---|
| 0 | `PERSP` | u, v — это su, tv (перспектива); иначе s, t (аффинно) |
| 1–2 | `LIGHT` | 0 — по lightmap, 1 — по вершинам (градиент `l`), 2 — без света, 3 — запас |
| 3 | `ZTEST` | рисовать, если `Z16 ≥ z` (или `>` при `ZGT`) |
| 4 | `ZWRITE` | записать `Z16` |
| 5 | `SKY` | `Z16 = 0`, тест `≥` всегда, z не пишется: небо ложится только туда, где z ещё 0 |
| 6 | `WARP` | волна Quake по s, t |
| 7–8 | `TRANS` | 0 — нет, 1 — 33 %, 2 — 66 % |
| 9 | `KEY` | тексель 255 прозрачен (ни цвета, ни z) |
| 10 | `ZGT` | строгий z-тест: мир идёт спереди назад, при равенстве остаётся первый (ближний) |

## Растеризация многоугольника

Многоугольник выпуклый, обход любой. Центр строки y — `yc = 16y + 8` (Q4).

1. Верхняя вершина `top` — первая (по номеру) с наименьшим y, нижняя `bot` — первая с наибольшим.
   Строки от `(y[top] + 7) >> 4` до `(y[bot] + 7) >> 4` (не включая), обрезка ножницами.
2. Две цепочки рёбер от `top`: A — вперёд по номерам (top → top+1 → …), B — назад (top → top−1 → …),
   обе до `bot`. В каждой — текущее ребро (p, q), в начале (top, сосед). Перед строкой yc ребро
   сдвигается дальше по цепочке, пока `q ≠ bot` и `q.y ≤ yc`.
3. Если в обеих цепочках `p.y ≤ yc < q.y`, край ребра
   `xs = ceil(((p.x − 8)·dy + (yc − p.y)·dx) / (16·dy))`, `dy = q.y − p.y`, `dx = q.x − p.x` (точно, int64);
   отрезок строки `[min(xsA, xsB), max(xsA, xsB))`, обрезка ножницами. Иначе строки нет.
   Левый край включается, правый — нет; верх включается, низ — нет: у соседних многоугольников нет ни
   щелей, ни двойных точек. Для выпуклого многоугольника это крайние края по всем рёбрам; в железе
   край идёт приращением по строкам (DDA), деление — одно на начало ребра.
4. Отрезок режется на куски по колонкам экрана в 16 точек: кусок — от x0 до `min(конец, (x0 | 15) + 1)`.
   Тогда кусок z — ровно одна пачка SDRAM 32 байта, кусок цвета — 16 байт.

## Точка многоугольника

- `zi` = градиент в точке. `Z16 = zenc(zi)`, у `SKY` — 0. `zenc` — «плавающее» 5+11 бит:
  zi ≤ 0 → 0; e — номер старшей единицы zi; e < 11 → zi; иначе `((e − 10) << 11) | ((zi >> (e − 11)) & 0x7FF)`.
  Монотонно; относительная точность 1/2048 на любой глубине.
- Аффинно: s, t — градиенты в точке.
- Перспектива: на концах куска x0 и x0 + n: `zc = max(zi, 2^15)`, `w = floor(2^46 / zc)` (≤ 2^31),
  `s = (su·w) >> 20`, `t = (tv·w) >> 20` (int64, сдвиг арифметический, результат — младшие 32 бита).
  Внутри: `ds = ((s1 − s0)·R[n]) >> 16`, `R[n] = floor(65536 / n)`; `s_k = s0 + k·ds`, k = 0…n−1.
  Конец куска — начало следующего: одно деление на кусок (у первого в отрезке — два).
- z-тест (`ZTEST` или `SKY`): z читается до текстуры; не прошла — точки нет.
- Волна (`WARP`): `s' = s + turb[((t >> 16) + фаза) & 127]`, `t' = t + turb[((s >> 16) + фаза) & 127]`
  (справа — s, t до правки); тексель берётся по s', t', свет — по s, t.
- Тексель TILED: `x = (s >> 16) & (W−1)`, `y = (t >> 16) & (H−1)`; при W ≥ 8 и H ≥ 8 — плитки 8×8:
  `адрес + (((y>>3)·(W>>3) + (x>>3)) << 6) + ((y&7) << 3) + (x&7)`, иначе `адрес + y·W + x`.
  LINEAR: `x = clamp(s >> 16, 0, ширина−1)`, `y = clamp(t >> 16, 0, высота−1)`, `адрес + y·шаг + x`.
- `KEY` и тексель 255 — точки нет.
- Свет по lightmap: `u = (s − smin) >> сдвиг`, `v = (t − tmin) >> сдвиг`;
  `iu = u >> 16`, `fu = (u >> 12) & 15`; если u < 0 — `iu = 0, fu = 0`; `iu ≤ клеток−1`,
  `iu1 = min(iu + 1, клеток − 1)`; так же iv, fv, iv1 по строкам. Клетки
  `L00 = lm[iv·клеток + iu]`, `L10 = lm[iv·клеток + iu1]`, `L01`, `L11` — в строке iv1;
  `val = (L00·(16−fu) + L10·fu)·(16−fv) + (L01·(16−fu) + L11·fu)·fv`; строка colormap `= val >> 10`.
  Клетка — байт `L = t_quake >> 6`, где `t_quake` — свет программного Quake 2 после `R_BuildLightMap`
  (`(255·256 − Σ) >> 2`, не меньше 64).
- Свет по вершинам: строка `= clamp(l >> 24, 0, 63)`.
- Цвет: `colormap[строка·256 + тексель]`; без света — тексель.
- Прозрачность (кадр — индекс, что уже лежит в точке): 33 % — `alphamap[цвет + кадр·256]`,
  66 % — `alphamap[цвет·256 + кадр]` (как `trans33/66` Quake).
- Запись цвета; `ZWRITE` (не у `SKY`) — запись `Z16`.

## Треугольники моделей (VBUF, STBUF, TRIS)

Зачем: треугольник модели в виде `POLY` — 16 слов (3 вершины и 12 слов градиентов); у модели вершины
общие, и одна вершина входит в ~5 треугольников. Поэтому вершины модели идут одной пачкой (`VBUF`),
координаты шкурки — другой (`STBUF`), треугольник — 2 слова номеров (`TRIS`), а плоскость треугольника
(градиенты) считает ПЛИС. Треугольники, которые программный Quake обрезал краем экрана или ближней
плоскостью, по-прежнему идут `POLY`.

Постановка треугольника (точно, целые числа; u, v — координаты вершины из `VBUF`):

1. `du1 = u1 − u0`, `dv1 = v1 − v0`, `du2 = u2 − u0`, `dv2 = v2 − v0`; `d = du1·dv2 − du2·dv1`.
   Если `d ≤ 0` — треугольника нет (обратная сторона или вырожденный; как `R_DrawTriangle` Quake).
2. Величины вершины: `zi`, `s = s_st << 16`, `t = t_st << 16`, `l = l_v << 16` (все int32).
3. Для каждой величины f (int64): `df1 = f1 − f0`, `df2 = f2 − f0`,
   `A = floor((df1·dv2 − df2·dv1) / d)`, `B = floor((du1·df2 − du2·df1) / d)` (деление с округлением вниз),
   `C = f0 − A·u0 − B·v0` по модулю 2^32; градиент — `{C, A, B}` (A, B — младшие 32 бита).
4. Многоугольник из трёх вершин `xy = (16u + 8, 16v + 8)` (целая точка Quake — центр точки адаптера)
   в порядке 0, 1, 2 рисуется как `POLY` с этим режимом и градиентами zi, s, t, l.

## Частица, картинка, заливка, кадр

- `POINT`: квадрат размер×размер, левый верхний угол (x, y), обрезка ножницами. В каждой точке —
  тест `Z16 ≥ z`, цвет (при прозрачности — через alphamap, как выше) и запись `Z16` на всех уровнях
  прозрачности (как `R_DrawParticle` Quake).
- `PIC`: точка (x + i, y + j), i < ширины, j < высоты, обрезка по экрану (не ножницами);
  тексель `адрес + ((j·шаг t) >> 16)·шаг строки + ((i·шаг s) >> 16)`; ключ 255 — прозрачен; без z.
- `FILL`: прямоугольник значением, обрезка по экрану. С затемнением — в 0 точки, где
  `(x & 3) != ((y & 1) << 1)` (как `Draw_FadeScreen` Quake).
- `FRAME`: нарисованный кадр показывается, рисуется второй. Вывод: `RGB = палитра[индекс]`, затем по
  каналу `RGB + (((вспышка − RGB)·A) >> 8)` (сдвиг арифметический).

## Чтение SDRAM по LINK (с 0.4)

Зачем: ESP держит в SDRAM ядра то, что ей самой нужно редко и понемногу, — кадры анимации моделей md2
(88 % их объёма; на уровень 0,2–1,3 МБ, в PSRAM ESP им не хватало места). Пишет она их командой `WRITE`
(как текстуры), а читает мимо очереди команд — регистрами LINK, пока ядро рисует.

| Адрес LINK | Имя | Смысл |
|---|---|---|
| 0x08 бит 6 | `RD_BUSY` | 1 — копия SDRAM → окно ещё идёт |
| 0x88 | `RD_ADDR` | W: адрес SDRAM (байтовый, кратен 32) |
| 0x8C | `RD_LEN` | W: пачек по 32 байта (1…128); запись запускает копию `RD_ADDR` … + 32·n в окно с его начала |
| 0x90 | `MARK` | R: число последней выполненной команды `MARK` |
| 0x1000…0x1FFC | окно | R: 4 КБ — то, что скопировала последняя копия (слово SDRAM, младший байт — младший) |

Порядок у ESP: загрузила данные `WRITE` → `MARK n` → перед первым чтением дождалась `MARK ≥ n` (данные
уже в SDRAM; очередь команд в ядре идёт по порядку). Чтение: `RD_ADDR`, `RD_LEN` → ждать `RD_BUSY = 0` →
слова окна. Копия не идёт через очередь: ей не нужно ждать, пока ядро дорисует кадр. Пока копия идёт,
окно не читать (там смесь старого и нового). Модель (`bz_read`, `bz_mark`) — то же без задержек.

## Пределы (ядро этапа B, `gpu/rtl/bz_core2.sv` + `bz_pix.sv`)

Модель считает и за этими пределами, ПЛИС — нет; передний край их не переходит.

- `LMAP`: клеток в строке и строк — не больше 64: lightmap многоугольника целиком лежит в слоте кристалла
  64×64 (у демо Quake 2 — до 17×17, с пересчётом под степень двойки — до 34×34). Больше — ядро ставит
  признак неверной команды.
- `PIC`: ширина·шаг s и высота·шаг t — меньше 2^31 (столбец и строка источника — меньше 32768), шаг строки
  — меньше 65536: точки картинки идут через тот же конвейер, что и текстура LINEAR.
- Адрес z-буфера — чётный (значение z не делится между словами SDRAM).

## Чего нет нарочно

Билинейной фильтрации текстур, RGB-кадра, перевода вершин, отсечения в 3D, градиентов из вершин —
это делает ESP или не нужно (`GPU.md`, «Почему не иначе»).

## Что изменилось против GPU.md

- z — не линейный 1/z, а «плавающий» 5+11: линейный на 2000 единицах давал шаг 16 единиц и мигание
  стыков, плавающий — 1 единицу.
- Обратное число — точное деление (последовательный делитель, 2 бита за такт, 16 тактов на кусок
  из 16 точек), а не таблица + Ньютон: проще описать бит в бит, а по времени укладывается.
- Куски выровнены по колонкам экрана (а не от начала отрезка): пачки SDRAM не рвутся.
- Добавлены `SETUP`, `SCISSOR`, режим `ZGT`; `PIC` с шагами Q16.16 (как `Draw_StretchPic` Quake).
- 0.4: `MARK` и чтение SDRAM по LINK (кадры md2 в SDRAM ядра).
